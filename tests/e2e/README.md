# 离线浏览器验收

这组测试在真正的 Chromium 中访问本机 FastAPI，并运行真实的上传、demo 候选与已配置图片模型的适配器、人工确认、SQLite 和 Excel 导出流程。它不是模型准确率测试，也不会调用真实模型 API。

## 可复现运行

在仓库根目录安装项目锁定的 Python / Node 依赖后执行：

```sh
uv sync --locked --python 3.12
npm ci
npx playwright install --with-deps chromium
npm run test:e2e
```

Linux 和 Windows 的 CI 使用相同配置。测试服务仅监听 `127.0.0.1:8765`，不复用已有服务。端口被占用时应停止测试并排查，不能将测试指向已有用户数据。

`serve.py` 使用系统临时目录建立数据库、原图与导出目录，启动时为 `demo`、禁止外传且不启用目录采集；不读取真实令牌文件或环境中的模型配置。源码中的令牌是公开的虚构测试值，仅用于这次可丢弃的本机服务。正常停止后临时目录被清理；强制终止可能留下带 `ocrs-playwright-` 前缀的临时目录，其中仍然只有虚构数据。

## 覆盖与产物

- 三个 Chromium 视口：390×844、1366×900、1440×1000
- 登录失败 / 成功、demo 提示、原生 Tab 顺序、上传弹窗焦点约束、Escape 恢复焦点
- 上传从零绘制的虚构 PNG，等待真实后台 worker 生成候选和受保护原图加载
- 编辑十进制值与前导零编号、切换任务保留草稿、队列搜索 / 筛选和原图缩放
- 取消最终确认不发确认请求 / 不增加订单，明确确认后只有一笔对应正式订单
- 正式订单搜索 / 筛选、历史中的操作者与原因，真实 XLSX 下载并使用 openpyxl 检查内容、精确小数、公式样式文本和未确认候选排除
- 只读配置页、退出与刷新后仍需登录、禁止外部浏览器请求、无应用运行异常
- 每个主要页面及对话框检查页面级横向溢出，并在 `test-results/` 保存截图；可在 `playwright-report/` 报告中查看附件

没有像素基准图，也没有自动声称“视觉通过”：截图是供人工检查的产物，断言覆盖的是明确的布局和行为约束。CI 上传截图、失败 trace 和完全虚构的 Excel 下载文件。

仅列出测试而不启动浏览器：

```sh
npx playwright test --list
```

配置或测试存在、语法检查和 `--list` 成功均不代表真实浏览器验收已执行或通过；须以具体 CI 运行结果和截图检查为准。

## 0.2.1 订单变更验收

order-changes.spec.cjs 通过真实界面和本机临时服务覆盖新单→改单 v2→撤单 v3、事件历史、精确 XLSX 状态、重复警告取消/显式确认，以及第二客户端造成版本冲突后的草稿保留与显式恢复。校验不直接修改数据库、不替换业务 HTTP 响应。每个现有视口运行三个新增场景，完整套件共 12 场景。


## 已配置图片识别验收

`recognition.spec.cjs` 在三个现有视口各运行四个场景：

- 从保存 `allow_external=false` 的配置开始，在上传处显式开启外部调用并授权本批图片；取消时不写授权、不上传，原文件仍保留。
- 核对发送配置版本、候选字段、识别证据文本、受保护原图，刷新及同来源重复上传不新增任务；人工取消不记账，确认后验证实际 XLSX 的精确金额。
- 不支持图片、非法 JSON、超时三种安全失败；均无 demo 回退或正式订单，取消重试不提交，变更模型后重新授权可恢复候选。

`serve.py` 只把 `PublicHTTPTransport` 替换成 `httpx.MockTransport`，不再替换 `recognize` 或 `test_connection`。图片编码、合成图片测试、响应解析/schema、后台 worker、HTTP API、SQLite 与 Excel 都走真实实现。替身校验图片 data URL 可解码，仅接受指定虚构主机和模型名，绝不联网。设置页失败测试也由该网络替身生成非法 JSON，不替换业务 API 响应。此验收不证明真实供应商可用或 OCR 准确率。

## 0.2.5 驳回复审与队列编辑验收

`review-resubmission.spec.cjs` 在三个现有 Chromium 视口各运行四个场景，共 12 个新增场景，完整套件共 45 个场景：

- 驳回后取消编辑或复审均不写入；保存人工修正保留驳回状态，明确提交复审后恢复待审核。双击只发送一次请求，同幂等键回放不重复记审计。
- 勾选、多选、本页全选和逐条编辑明确范围；51 次真实虚构图片上传产生两页，搜索、筛选、刷新与翻页清空选择，保存仅影响当前编辑任务。
- 两条已驳回记录多选后，首条复审离开已驳回筛选，仍可继续编辑第二条，不覆盖首条。
- 第二客户端真实写入产生 409，保留本地草稿，丢弃并重新载入需明确确认；非法复审状态及同键不同载荷均拒绝写入。

这些场景不直接修改数据库，也不替换业务 HTTP 响应。短暂延迟本机请求用于验证双击锁和旧版本冲突，随后继续请求真实服务。断言原始模型候选、来源、识别次数、模型配置版本与外传授权保持不变，正式订单与导出状态不因复审改变；截图展开并检查驳回、修正及复审原因。测试数据和图片完全虚构，范围不包含真实供应商、真实业务数据或当前用户服务更新。

## UI 细节与可访问性验收

`ui-polish.spec.cjs` 在三个现有 Chromium 视口各运行三个场景，共 9 个新增场景。检查本地 SVG 的统一网格、`currentColor` 与不缩放描边；在导航点击的同一事件周期核对 `aria-current` 和视图可见性；测量默认输入边框与实际合成背景的 3:1 对比度、手机重要触控目标的 44px 尺寸和页面水平溢出。

键盘检查使用真实 Tab / Shift+Tab 顺序，验证可见焦点、导入与复审对话框的焦点约束和 Escape 恢复。按压检查在真实指针按下期间读取计算样式，核对允许动效时的 0.96 / 150ms / ease-out、导航和禁用控件不缩放；减少动效时核对不缩放及对话框实际 opacity 过渡。强制颜色模式检查阴影消失后结构边框仍可见，滚动对话框保持 `overscroll-behavior: contain`。

审核截图来自真实上传、demo 候选、API 驳回和浏览器编辑流程，取消复审后业务记录必须保持相同。所有页面与对话框截图保存为测试附件；不调用真实模型、不使用真实订单，也不把访问令牌放入截图或 URL。这些检查与截图提供可复核证据，不代表未执行的浏览器验收已通过。

## 来源无关识别边界验收

recognition-boundary.spec.cjs 在三个现有视口验证真实正式单图接口与只读结果页面：上传后直接读取未核实结果，缺失数量/价格与未知 SKU 不阻塞结果；原图由鉴权 blob 显示，模型原始结果不会被可选审核修正覆盖。仅按需进入原审核，不新增正式订单。

场景用真实 Tab/Enter 操作上传、结果 JSON 展开、可选审核和 API 导航/鉴权 OpenAPI 查询，检查页面水平溢出并保存上传主页、上传对话框、原始结果、API 指南与契约截图。原 recognition.spec.cjs 真实配置上传已适配正式识别入口，结果读取后显式选择可选审核，继续覆盖旧复审及 Excel 工作流。所有图片、模型返回和凭据均为虚构离线替身，截图不得提交到仓库。
