# 订单审核工作台设计

## 目标与边界

0.2 系列面向单人、单机的高密度订单审核。保留 FastAPI、原生 JavaScript 与 SQLite，不为视觉重做引入运行时框架、远程字体或 CDN。截图是证据，模型结果是候选，只有人工确认才成为正式订单；界面不能把演示数据、已填配置或成功请求包装成识别准确性保证。

## 参考资料及采用方式

- [Carbon 数据表](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)：清楚的列、状态、筛选、空结果与行级操作，保持可扫描的信息密度。
- [Ant Design 数据展示](https://ant.design/docs/spec/data-display-cn/)：中文后台的信息层级、有效对齐与异常提示。
- [Linear 自定义视图](https://linear.app/docs/custom-views)：按实际工作状态定位队列，保留筛选上下文。
- [Material 语义色](https://m3.material.io/styles/color/the-color-system)：主题色与等待、处理中、需复核、已完成、失败等状态色分离。
- [WCAG 2.2](https://www.w3.org/WAI/WCAG22/quickref/)：键盘、可见焦点、标签、错误提示、缩放与窄屏可用性。引用标准不代表已获得无障碍认证。

参考的是交互原则，不复制组件代码或宣称使用其组件库。

## 信息架构

- 工作台：下一步待办、真实运行状态与导入入口。
- 审核队列：搜索、状态筛选、分页；当前页勾选、多选和逐条编辑，清楚展示选中范围。进入详情后对照原图与候选字段，返回保留筛选上下文；搜索、筛选、分页与显式刷新清空选择。
- 审核详情：桌面证据与表单双栏；原图缩放、来源、候选警告、审核人、原因与明确确认操作。没有证据坐标时不生成虚假的定位框。
- 正式订单：检索当前订单及其历史。改撤单仍走有证据、有版本、有原因的人工确认流程。
- 导出中心：区分正式订单、待导出事件与最新快照状态；失败不会撤销订单。
- 运行配置：页面维护模型设置，保存与测试分离，密钥只写后端；下方安全白名单展示只读诊断。真实图片处理仍需明确目的地及批次授权；备份恢复继续使用停机 CLI。

## 视觉与交互

使用中文系统字体和低噪声浅色面板，紧凑导航、统一输入与按钮、明确的主次/危险操作。状态同时显示文字，不能只靠颜色。桌面侧栏与移动布局使用同一业务语义，不隐藏关键警告。

- 加载、无任务、筛选无结果、失效令牌、连接失败、字段错误、版本冲突分别反馈。
- 提交期间锁定重复操作；成功与未知结果不得混淆。
- 轮询和旧请求不得覆盖当前人工输入或新会话；退出清除受保护数据及原图 URL。
- 数量与金额保留十进制字符串，显示不使用浮点运算改写业务值。
- 已驳回候选允许保存修正后明确提交复审；保存保持驳回状态，复审只恢复待审核。详情展示原驳回理由及版本历史，正式确认仍单独执行，不因复审调用模型。
- 浏览器输入使用实际 label/button，提示使用适当的 live region；对话框需支持关闭与焦点返回。
- 快捷键不能干扰文本编辑或中文输入法组合输入。

## 0.2.6 表面、图标和动效

本次使用 [jakubkrehel/skills 的 better-ui](https://github.com/jakubkrehel/skills/blob/d574cc8a576dc24256ad38268b8d03d86724a1b3/skills/better-ui/SKILL.md)，来源固定为 `d574cc8a576dc24256ad38268b8d03d86724a1b3`（MIT）。同时参考包内 layout、typography 与 accessibility；技能仅作为设计约定，不执行其外部命令示例。

保留当前蓝色 token、原生组件、系统字体和高密度表格。纯深度表面使用精确的三层浅阴影与透明边框，结构分隔、表格、选择及输入边框保持明确；均匀嵌套表面按内圆角加 padding 和 border 推导外圆角。图像边缘为纯黑 10% 的 1px 内描边；同套本地 20px SVG 使用 currentColor 和不随缩放变化的描边，导航选中态即时改变。

启用按钮按压缩放到 `0.96`，`150ms ease-out`；列表、导航、原图工具和显式静态控件保持稳定。hover 仅在支持悬停的设备生效。对话框透明度进入/退出为 `300ms/150ms`，允许动效时再加入 `12px/-12px` 位移和 `4px` 模糊；减少动效模式只有透明度反馈。没有增加导航或行级级联动画、动画库、主题切换或预设 will-change。

模型表单增加统一内容 inset。窄屏主要操作区至少 44px、输入文字 16px；横向表格和证据区域可通过键盘聚焦滚动。提交状态同时提供文字与 aria-busy，成功关闭后原触发器不再存在时使用可见的上下文焦点位置。全局快捷键跳过组合输入、已处理事件及文本编辑。
