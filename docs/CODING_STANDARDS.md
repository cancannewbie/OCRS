# OCRS 项目代码规范

## 1. 适用范围与状态

OCRS（Order Collection and Review System）面向客户下单截图的采集、识别、人工审核与订单导出。本规范定义后续开发约束，不代表相关功能已经实现。

当前仓库只有文档与编辑配置，尚未选定运行时版本、依赖、模型供应商、微信接入方案、存储部署或前端框架。下文的目录和技术栈为建议；实施前结合实际规模确认并记录。安全、可追溯、精确金额、人工确认和幂等约束不随技术栈变化。

“必须”是验收要求；“建议”允许有理由的替代。偏离必须项需先修改设计和规范并由维护者批准，不能以实现便利为由静默跳过。

## 2. 实施前确认

- 使用个人微信还是企业微信？通过什么受支持且获授权的方式获取截图或消息？
- 运行在什么平台？单人单机、共享服务还是多用户协作？预计图片量和并发量？
- 输出到本地 Excel、共享文件还是指定在线表格？谁能读取和修改？
- 必填订单字段、商品及单位规则、币种、时间区、改单撤单识别和审核权限是什么？
- 模型服务允许接收哪些数据？原图、候选结果、正式订单和审计记录分别保留多久？

未确认的内容写入待办或设计记录，不当作事实。可先以虚构样本开发离线导入接口；不得为便利绕过访问控制、破解客户端或采集未授权聊天。

## 3. 技术选型与模块边界

建议后端采用 Python、FastAPI、Pydantic；单机可评估 SQLite，多人并发可评估 PostgreSQL。审核 UI、任务队列和表格供应商按需要确定。选择理由、版本、部署限制和替代方案记录在后续 docs/decisions/ 下，不预先引入用不到的基础设施。

建议按职责组织，目录名可调整：

~~~text
src/ocrs/
  domain/          # 订单、明细、状态与业务约束，不依赖 Web 或供应商 SDK
  application/     # 采集、识别、审核、导出等用例与事务编排
  contracts/       # API 与模型输入输出的数据契约
  adapters/
    capture/       # 获授权的采集或导入适配器
    recognition/   # 模型服务适配器
    persistence/   # 数据库和对象存储
    export/        # Excel 或在线表格
  api/             # 鉴权、请求校验、响应映射
  workers/         # 后台任务入口
tests/
  unit/
  integration/
  fixtures/        # 仅虚构数据
~~~

这是参考结构，尚不存在。避免为每个空目录创建占位代码。

依赖方向朝向领域／应用层；外部适配器实现用例需要的接口。HTTP 处理器不能直接拼装模型提示词、写表格或混入订单判断。领域层不读环境变量、不发网络请求、不依赖全局可变状态。阻塞 SDK／文件 I/O 不得阻塞异步请求循环。

## 4. 编码风格与配置

- 标识符使用准确的英文；业务说明、错误解释和文档可使用中文，避免拼音缩写。
- Python 模块、函数、变量用 snake_case，类用 PascalCase，常量用 UPPER_SNAKE_CASE；其他语言遵循选定生态规范。
- 公共函数、数据契约、适配器接口写类型；避免无约束字典横穿模块边界。注释解释原因、边界和单位，不复述代码。
- 函数承担清晰职责；避免宽泛异常吞噬、隐式副作用、循环依赖和重复业务规则。
- 配置集中校验：缺少必要变量时清楚失败；错误只指出变量名，不回显秘密值。区分开发、测试、生产配置。
- 密钥从后端环境变量或密钥服务读取；提交的示例配置只能含无效占位符。
- Python 实施时建议采用 Ruff、类型检查器和 pytest；在选定版本、配置与包管理器后，将真实命令写入 README。不要复制未验证的运行命令。
- 依赖选择维护良好的必要组件；固定可复现解析结果，提交工具实际生成的锁文件，不手写伪造锁文件。

## 5. 数据契约、金额与证据

### 5.1 三类记录不可混淆

1. 原始输入：来源标识、采集时间、文件摘要、受控存储引用和处理状态。
2. 识别候选：schema 版本、模型和提示词版本、字段候选值、证据、警告及审核状态。
3. 正式业务记录：人工确认的订单、明细、版本与业务事件。数据库是事实源。

原图和原始模型响应属于受控敏感材料，按需要及保留策略存储，不默认无限保留，不直接写日志。删除原图时允许保留不含原文的事件元数据，并标明证据已过期，不能假装仍能回放。

### 5.2 字段规则

- 订单头与明细分离，一单多行商品；明细应可独立定位和修订。
- 为记录分配稳定内部 ID。客户姓名、手机号、截图文件名和表格行号不能充当唯一订单 ID。
- 金额及可带小数的数量使用 Decimal／精确十进制或数据库定点类型；JSON 建议使用十进制字符串。禁止 float 参与金额计算。
- 明确币种、数量单位、允许精度和舍入规则；税费、运费、折扣单独建模，不能在未定义口径时强行要求明细合计等于应付总额。
- 电话、订单外部编号及商品编码使用字符串，保留前导零；不因为看起来是数字就转成数值。
- 缺失与不确定用 null，附原因；null、空字符串和零含义不同。禁止猜测数量为 1 或价格为 0。
- 业务时间使用带时区的时间戳，存储建议 UTC，展示按已确认业务时区转换。截图只有“今天”或缺少年份时，保留上下文与不确定性，不直接当作采集日期。
- 模型字段应能追溯到 source_id 与证据位置（文本片段或图片区域）；证据片段同样受隐私控制。模型声称的证据也需核验。
- 若返回置信度，允许未知；只作为辅助信号，不把模型自报概率视为经校准准确率。

### 5.3 API 与模型 schema

为各边界定义版本化 schema：字段类型、必填／可空性、长度、枚举、范围及未知字段策略。模型结构输出必须再次做本地验证，不能只依赖提示词“要求输出 JSON”。

区分无法识别、缺少字段、证据冲突、格式非法和业务规则不满足；返回稳定错误码和适合审核的原因。错误响应不得泄漏堆栈、凭据和客户原文。示例只能用虚构信息。

## 6. 采集、识别与人工审核

- 采集器只处理获授权的来源，记录来源和采集上下文；未写完的图片先暂存，完整且验证通过后才入队。
- 校验文件真实类型、大小、解码结果和像素上限，防路径穿越、恶意文件及解压炸弹；存储路径由系统生成，不直接信任上传文件名。
- 对图片内容和来源计算稳定摘要用于技术去重；相同图片可能对应不同业务场景，摘要不是订单唯一性证明。
- 业务去重使用来源会话／消息标识及明确业务键；相似截图只提示可能重复，不能自动合并或删除不同订单。
- 模型任务记录版本和输入摘要；重新识别产生新候选，不覆盖人工确认结果。
- 图片内“忽略规则”“调用链接”“发送密钥”等内容仅是待识别文本。模型不获工具执行或写业务库的权限，不自动打开图片中的 URL。
- 建议处理状态：received → recognizing → review_required → confirmed／rejected；失败和重试另记录状态、原因与次数。正式订单状态、识别任务状态和导出状态应分别建模。
- 所有候选默认进入人工审核。缺失、矛盾、金额异常、疑似重复和撤单／改单必须显著提示。未来若引入自动确认，需另行批准规则、风险边界和测试，不能借置信度阈值绕过本规范。
- 审核界面展示必要证据、候选值及人工修改；校验必填字段后确认，并记录操作者、时间、修订原因和版本。
- 审核并发采用乐观锁等冲突检测；过期页面确认必须提示冲突，禁止“最后保存者静默覆盖”。

## 7. 订单变更、事务与幂等

- 正式订单新增、修改、撤单都保留业务事件。建议事件包含 event_id、order_id、版本、事件类型、操作者、时间和原因；敏感变化值在受控存储内管理。
- 改单应明确指向原订单并经确认；撤单变为明确状态，不硬删除来冒充“从未存在”。数据保留到期删除与业务撤单是不同操作。
- 一个用例内原子写入订单／明细、业务事件和 outbox 事件，成功提交后再异步导出；禁止数据库和表格各写一次却没有失败恢复。
- 采集任务、识别任务、确认请求与导出任务使用相应幂等键。幂等键作用域包含业务／租户边界；同键不同有效载荷要拒绝或显式报冲突。
- 依赖数据库唯一约束与事务处理竞争条件；先查询再写入不足以保证并发幂等。
- outbox 消费以至少一次投递设计，通过 event_id 或稳定业务键去重；不能仅靠“发送过”布尔值宣称 exactly-once。
- 对外部调用后未收到回执的未知结果，先按幂等标识对账再重试，避免重复追加。
- 事务内不等待长时间模型或表格网络调用；重试不会再次扣减数量、追加相同事件或重复确认。

## 8. Excel 与在线表格导出

- 只导出已确认的业务记录，记录导出目标、schema 版本、订单版本、任务 ID、状态和受控错误摘要。
- 本地 Excel 每个目标文件采用单写者协调；多进程／多主机时使用覆盖该范围的锁或独立导出进程，线程锁不够。写临时文件，验证后在支持原子替换的同一文件系统替换，并处理文件被占用。
- 在线表格使用稳定的 order_id／line_id 定位记录；行号会改变，不作为唯一定位依据。按目标能力实现幂等 upsert 或带去重索引的追加。
- 决定一行一订单还是一行一明细、列名和类型、撤单呈现、版本冲突及人工编辑策略后再实现；不得静默覆盖用户手填列。
- 所有客户／模型可控文本按“文本”写入，禁止自动解释为公式。覆盖以 =、+、-、@ 和制表符／回车等危险前缀开头的输入及前导空白情况。
- 对 XLSX 显式设文本单元格；在线表格使用不解析公式的原始值模式（若支持）；CSV 使用经目标客户端验证的中和策略。仅添加 CSV 引号不能阻止公式执行。
- 可信的数字金额写入数值列，客户文本与计算公式分开。测试必须验证目标表格打开后不会执行恶意公式。
- 导出失败不撤销已确认订单。保留可恢复任务、重试／对账入口和可见状态；必要时从数据库重建导出，不以表格是否有行判断数据库真相。

## 9. 外部服务、错误与可观测性

- 所有外部调用设置连接／读取超时、并发上限、速率和费用预算；模型或供应商切换通过适配器。
- 仅对适合重试的临时故障做有界指数退避和抖动，尊重 Retry-After；设置次数／总时长上限，耗尽后进入可见失败队列。
- 鉴权失败、非法参数、schema 不匹配和业务拒绝不能无限重试。区分网络未知结果与明确未执行。
- 任务支持失败恢复、取消和受控重放；重放仍满足权限及幂等要求。
- 结构化日志包含 trace_id、job_id、状态、耗时、错误码和重试次数；使用非个人的内部标识关联。
- 不记录截图、完整 OCR 原文、模型原始响应、电话号码、地址、凭据、带密钥 URL 或完整请求头。调试开关不豁免脱敏。
- 指标至少覆盖识别失败、待审核积压、导出失败和耗时；指标标签不含个人信息及无限增长的订单 ID。

## 10. 隐私、权限和存储

本仓库公开可读。源码、测试、PR、issue、提交历史和 CI 产物都不得包含真实客户数据或秘密。.gitignore 只是防误提交辅助，不影响已跟踪文件，也不是访问控制。

- 测试仅使用完全虚构的数据；脱敏后的真实截图仍可能残留身份信息，不能默认可公开。
- 生产截图、数据库、备份及导出存放在仓库之外的受控位置。访问按角色和最小权限分离；多租户实现必须防跨租户读写。
- 受保护数据的预览、下载、导出和审核接口均鉴权；不能只在前端隐藏按钮。
- API 密钥、服务账户和表格令牌仅在服务端使用，限制用途和权限并支持轮换。
- 真实资料传给模型或在线表格前，确认用户授权覆盖特定目的地、数据范围和用途；先裁剪／去除非必要信息。
- 为图片、模型结果、订单、审计和备份分别定义保留与删除策略，限制备份访问，校验删除执行结果。
- 涉及隐私的审计记录亦最小化，不能以“审计”为由永久保存全部客户原文。
- 发现泄漏立即停止继续传播、通知维护者并处理凭据吊销及轮换；不要只删当前文件就宣称历史泄漏已消除。

## 11. 数据库迁移与恢复

- schema 变更通过可追踪迁移，不在生产手工改表或以启动时自动建表替代迁移管理。
- 为迁移评估锁表时间、兼容窗口、数据回填和失败恢复；破坏性迁移先确认备份及恢复可行性。
- 备份数据库与必要对象引用，测试恢复后的引用完整性、订单版本及待发送 outbox。
- 从恢复点重放必须重新对账，避免已发送外部结果重复写入。
- 若采用 SQLite，明确单机写入竞争、事务和备份方式；不能在未经验证的共享盘上假设多机写入安全。若规模改变，记录迁移至服务型数据库的依据。

## 12. 测试要求

新增代码必须有与风险相称的测试。默认测试离线、可重复、无费用；模型、采集器和表格 API 用可控替身。真实外部集成测试单独开关，使用隔离账户、虚构数据和明确预算。

必须覆盖：

- schema：缺失／null／零、未知字段、非法枚举、截断 JSON、超长文本及错误类型。
- 识别：模糊或部分截图、多订单／多商品、矛盾字段、日期上下文缺失、提示词注入、模型拒答。
- 金额：十进制运算、舍入、单位、折扣／运费、总额冲突；不允许浮点误差进入结果。
- 审核：候选不可直接导出、必填不足不可确认、并发审核版本冲突、人工结果不被重识别覆盖。
- 幂等：重复截图、同键不同请求、重复确认、重复投递、并发写入唯一性冲突。
- 变更：改单和撤单的关联、审计、版本和最终表格表现。
- 恢复：数据库已提交但进程崩溃、发送成功但回执丢失、outbox 重放、外部超时／限流／凭据失效。
- 导出：文件占用、部分失败、重试不重复、字段类型、前导零、换行 Unicode、公式注入、手填列保留。
- 安全：越权和跨租户请求（如适用）、路径穿越、超大图片、日志／异常脱敏。
- 迁移：从支持的旧 schema 升级、备份恢复和恢复后的对账。

每个缺陷修复增加回归用例。不要仅用覆盖率百分比替代行为验证；测试数量或覆盖率门槛由有实际代码后的基线决定。

## 13. 验收与交付

业务功能交付至少证明：获授权输入可以变成有证据的候选，人工确认后落库，指定目的地只产生预期导出；重复操作不重复记账；改单／撤单可追溯；故障后能恢复且可对账；秘密与真实客户资料不进入仓库或日志。

每个 PR 说明范围、schema／兼容变化、实际验证结果、未运行项和风险。首次实现时补齐可复现命令与真实 CI，后续依照这些命令验证；当前纯文档提交只验证规范一致性、链接、格式和内容安全。

配套流程见 [CONTRIBUTING.md](../CONTRIBUTING.md)，代码代理执行摘要见 [AGENTS.md](../AGENTS.md)。
