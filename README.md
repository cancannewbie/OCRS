# OCRS

Order Collection and Review System：把获授权的下单截图变成可人工审核、可追溯的订单，并生成本地 Excel 快照。

当前版本面向**单人、单机、本地运行**：Python 3.12、uv、FastAPI、原生 JavaScript、SQLite。不接入微信客户端，不读取聊天记录，不提供云端部署或多用户权限体系。微信截图由操作者手动保存，再上传或导入受控目录。

## 能做什么

- 导入图片，保存原始证据、摘要和来源上下文，识别结果始终是待审核候选。
- 同一图片与同一来源标签的重复导入复用来源；业务上疑似重复只提示，不自动合并订单。同图属于不同场景时，明确使用不同来源标签。
- 人工修改并确认新单、改单或撤单；保存订单/明细、版本、操作者、原因、事件与 outbox。
- 只从已确认订单生成 XLSX 快照。每次生成新文件，不修改用户已经编辑过的表格。
- 使用本地访问令牌保护业务 API，支持停机备份、恢复到新目录、显式清理过期图片。

**默认 demo 模式不会读取图中文字，也不是真实 OCR。** 它返回醒目标记的虚构订单，供验证流程；不能用来测识别准确率或处理真实订单。真实模型适配器需要单独配置并明确允许外传，详见[运维说明](docs/OPERATIONS.md)。

## 本地演示

前提：已安装 Python 3.12 和 [uv](https://docs.astral.sh/uv/getting-started/installation/)（本地及 CI 基线为 0.12.23）。在仓库根目录执行：

```sh
uv sync --locked --python 3.12
uv run --locked ocrs init
uv run --locked ocrs token
uv run --locked ocrs serve
```

1. 在浏览器打开 <http://127.0.0.1:8000>，粘贴 `ocrs token` 显示的本地访问令牌。
2. 上传一张**完全虚构**的订单图片，填写可辨识的来源标签；上传后开始识别。
3. 核对原图、警告和候选字段，补充或修改客户、商品编码、品名、数量、单位、单价及币种。默认商品目录只包含 `DEMO-001`。
4. 人工确认后查看正式订单；需要更改或撤销时，明确目标订单、当前版本与原因。
5. 生成并下载 Excel 快照。未确认的候选不会进入正式订单导出。

终端按 `Ctrl+C` 停止服务。数据库、图片、令牌与导出默认保存在仓库之外的 `~/.ocrs`；可通过 `OCRS_DATA_DIR` 改变位置。不要把令牌、真实截图或导出粘贴到 issue、PR 或公开日志。

## 配置与边界

配置示例见 [.env.example](.env.example)，完整解释、真实模型启用、受控目录导入、备份恢复及证据清理见 [OPERATIONS.md](docs/OPERATIONS.md)。

- 默认监听 `127.0.0.1:8000`，只在可信本机使用。单一访问令牌不等于多用户身份或角色隔离。
- SQLite 与文件锁要求本机单写者；不要在共享盘、多主机或多 worker 下运行。
- 金额采用精确十进制，数量和价格不使用二进制浮点；本版支持 CNY、USD、EUR、GBP、JPY。
- 商品目录由 `OCRS_SKUS` 配置；未知编码、缺失字段和无效目标版本需人工处理。运费、税费、折扣、库存和会计结算未建模。
- 每张图片可产生多个候选动作；模型不能执行图片里的指令、打开链接或直接写入正式订单。
- 图片保留窗口默认 30 天，**不会自动删除**。显式清理会同时删除对应候选及候选历史；正式订单、事件与审计资料没有自动到期删除功能。
- 本版不含在线表格同步、微信自动采集、供应商费用结算或生产准确率承诺。

## 开发与验证

测试使用虚构数据、临时数据库与模型替身，默认不调用付费模型。安装锁定依赖后执行：

```sh
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy src
uv run --locked pytest
uv build
```
