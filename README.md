# OCRS

OCRS 接收获授权的截图，调用模型提取信息，并提供未经人工核实的结构化结果。图片来源由调用方负责，通过正式 API 接入或在页面手动上传。

当前版本面向**单人、单机、本地运行**：Python 3.12、uv、FastAPI、原生 JavaScript、SQLite。系统不负责数据来源采集，不接入微信客户端、不读取聊天记录、不监听桌面或目录，也不提供云端部署或多用户权限体系。已有人工审核、订单与 Excel 导出保留为可选下游。

## 能做什么

- 页面手动上传，或通过 `POST /api/recognitions` 提交一张图片并立即取得任务 ID，再查询状态和结果；无需先完成审核。
- 保存原图证据、摘要、可选来源备注和模型候选；缺失字段保留 `null`，金额与数量使用精确十进制字符串。未知商品编码不阻塞读取原始提取结果。
- 同一图片与同一来源标签复用原任务；外部幂等键提供持久重放与冲突检测。同图属于不同场景时，明确使用不同来源标签，技术去重不证明订单相同。
- 按需进入原人工审核，确认新单、改单或撤单，保存订单/明细、版本、操作者、原因、事件与 outbox。
- 可选 XLSX 只从已确认订单生成，每次产生新快照，不修改用户已经编辑过的表格。识别结果不等于确认订单入账。
- 使用本地访问令牌保护业务 API，支持停机备份、恢复到新目录、显式清理过期图片。

**默认 demo 模式不会读取图中文字，也不是真实 OCR。** 它只供显式离线演示，正式识别 API 在 demo 下返回 `MODEL_NOT_CONFIGURED`，不会用虚构候选冒充识别结果。真实模型在登录后的“模型设置”页面配置，每次图片提交或重试还需明确当前目的地和本次图片外传范围；API 入口不默认授权外传。详见[接口文档](docs/RECOGNITION_API.md)与[运维说明](docs/OPERATIONS.md)。

## 本地演示

前提：已安装 Python 3.12 和 [uv](https://docs.astral.sh/uv/getting-started/installation/)（本地及 CI 基线为 0.12.23）。在仓库根目录执行：

```sh
uv sync --locked --python 3.12
uv run --locked ocrs init
uv run --locked ocrs token
uv run --locked ocrs serve
```

1. 在浏览器打开 <http://127.0.0.1:8000>，粘贴 `ocrs token` 显示的本地访问令牌。
2. 首次保持默认 demo；如需真实识别，先在“模型设置”页面选择供应商、模型与地址，填写密钥并保存。无需模型配置文件或重启；保存不调用外部服务。
3. 在“上传识别”选择**完全虚构**的图片与可选来源备注；真实模型会要求确认目的地、图片外传与可能费用，再逐张通过正式单图接口提交。默认 demo 只能通过明确标识的“运行离线演示”验证旧审核流程，不执行 OCR。
4. 在“识别结果”查询处理状态并对照原图读取字段、证据与警告；此时无需人工确认或匹配商品目录。
5. 如需订单工作流，再进入可选审核，补充和核对字段并人工确认；改单或撤单须明确目标订单、当前版本与原因。
6. 如需 Excel，再从正式订单生成并下载快照。未确认的候选不会进入正式订单导出。

终端按 `Ctrl+C` 停止服务。数据库、图片、令牌与导出默认保存在仓库之外的 `~/.ocrs`；可通过 `OCRS_DATA_DIR` 改变位置。不要把令牌、真实截图或导出粘贴到 issue、PR 或公开日志。

## 工作台导航

主导航突出“上传识别”“识别结果”“API 接入”，页面上传与外部调用共享本地提取流程。结果支持分页与搜索，显示处理状态，可直接读取未审核的模型结果。API 接入说明单图提交、授权、轮询和错误处理，鉴权 OpenAPI 位于 `/api/openapi.json`。原审核队列、正式订单与导出为可选下游；审核队列继续支持状态筛选，详情支持对照原图、保留返回上下文。

运行配置继续提供模型设置。模型配置保存、配置完整和连接测试通过是不同状态；测试只发送系统生成的虚构图片与 schema，可能计费，不证明生产识别准确率。备份恢复仍需先停机后使用 CLI。

审核队列可勾选当前页的可编辑记录，再逐条编辑；切换搜索、筛选、分页或显式刷新会清空选择。已驳回记录可保存修正，再明确提交复审，恢复为待审核；不会重新调用模型或生成正式订单。原驳回理由、模型候选和人工修订历史可在详情核对，正式确认仍是独立操作。设计与接口边界见 [驳回复审决策](docs/decisions/0005-rejected-review.md)。

版本变化见 [CHANGELOG](CHANGELOG.md)，设计依据见 [UI_DESIGN](docs/UI_DESIGN.md)。

## 配置与边界

模型配置只在页面维护，不需要编辑 `.env` 或模型配置文件。可选本地路径、访问令牌和下游商品编码配置见 [.env.example](.env.example)。`OCRS_INBOX` 从 0.3.0 起被忽略，不启动目录采集；已有图片与任务保留。完整解释、升级、真实模型启用及备份恢复见 [OPERATIONS.md](docs/OPERATIONS.md)。

从 0.2.2 升级：先停机备份，再安装锁定依赖并运行 `ocrs init`（业务 schema 1 → 2）；启动登录后重新填写模型设置。所有旧模型环境变量均被忽略，不自动导入，也不覆盖页面保存值；旧 `.env` 中的密钥需自行安全移除。模型密钥在独立存储中加密，内置业务备份不包含模型配置或主密钥，恢复后须重新配置。

升级到 0.2.5 同样需停机备份并执行 `ocrs init`：业务 schema 2 → 3 新增人工候选修订和审计版本；schema 1 会依次升级。已有订单、模型配置及驳回理由保留。旧程序不支持 schema 3，回退须用升级前备份恢复到新目录，详见 [升级步骤](docs/OPERATIONS.md)。

升级到 0.3.0：先停机备份，再安装锁定依赖并执行 `ocrs init`（schema 3 → 4，新增正式识别请求的持久幂等映射）。不删除已有来源、任务、候选、订单、审计或模型设置。旧 `/api/uploads` 保留兼容与显式 demo 演示，新接入使用 `/api/recognitions`。停止目录扫描后，外部来源需改为 API 或手工上传；回退须使用升级前备份恢复到新目录。

- 默认监听 `127.0.0.1:8000`，只在可信本机使用。单一访问令牌不等于多用户身份或角色隔离。
- SQLite 与文件锁要求本机单写者；不要在共享盘、多主机或多 worker 下运行。
- 金额采用精确十进制，数量和价格不使用二进制浮点；本版支持 CNY、USD、EUR、GBP、JPY。
- 商品目录由 `OCRS_SKUS` 配置，仅影响可选正式订单确认；未知编码、缺失字段和无效目标版本需人工处理，但不阻塞提取结果查询。运费、税费、折扣、库存和会计结算未建模。
- 每张图片可产生多个候选动作；模型不能执行图片里的指令、打开链接或直接写入正式订单。
- 图片保留窗口默认 30 天，**不会自动删除**。显式清理会同时删除对应候选及候选历史；正式订单、事件与审计资料没有自动到期删除功能。
- 正式 API 每次单图，PNG/JPEG/WebP 最多 10 MiB、2,000 万像素；单进程顺序识别，待处理容量为 100。完整限制与可恢复错误见 [接口文档](docs/RECOGNITION_API.md)。
- 不抓取外部图片 URL，不支持回调/webhook；本版不含在线表格同步、微信采集、供应商费用结算或生产准确率承诺。

## 开发与验证

测试使用虚构数据、临时数据库与模型替身，默认不调用付费模型。安装锁定依赖后执行：

```sh
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy src
uv run --locked pytest
uv build
```

前端回归另需 Node.js 22（运行应用本身不需要 Node）：

```sh
npm ci
npm run test:frontend
npx playwright install --with-deps chromium
npm run test:e2e
```

浏览器验收在临时数据目录使用虚构图片与 demo；不调用付费模型。测试截图由 CI 保留为产物，不上传业务资料。完整范围与未验收项见 [验收矩阵](docs/ACCEPTANCE.md)。

[CI 配置](.github/workflows/ci.yml) 在 Linux/Windows 的 Python 3.12 下执行这些检查，不部署服务。命令与配置的存在不代表某次提交已通过；实际结果以该次运行记录为准。
